# 03：訊息正文整理與本地預覽

Status: ready-for-human
Blocked by: None（沿用切片 A 與選填範圍）

依使用者授權，完成先前提出的下一小段：從頻道取得一般對話，組成可檢查的文字資料，不呼叫 LLM。

- 使用既有允許清單、Bot／請求者權限與 hours／limit 選取規則。
- 原始訊息先套用筆數上限，系統通知再排除，不補抓更舊訊息；回報原始、系統、空內容及可用筆數。
- 保留訊息 ID、使用者 ID、當前伺服器暱稱、時間、正文、附件佔位符、回覆來源 ID 及原文連結。Bot 一般文字也可納入。
- 成員已離開時以可得的全域顯示名稱／username 回退；每個發言者每次查詢只解析一次暱稱。
- 文字依時間與 ID 排序，跨日加日期，預設台灣時間且沿用設定；保持 `暱稱 (HH:mm) : 內容`。多行與控制字元轉為可見跳脫，原文完整保存在來源資料。
- 本地 CLI 須明確指定 requester ID，權限檢查成功後才能輸出到 local-exports；不新增 Discord 原文自動回傳，不讀外部 URL／附件。
- 提供虛構資料的離線預覽與測試；真實正文非空驗證若未執行，明示待驗證。

測試介面：SummaryApplication.prepare 的可觀察結果、Discord adapter 的 HTTP 邊界，以及預覽 CLI。沿用既有規格與已授權測試介面，不額外訪談。

範圍外：機密遮罩、LangChain、模型、排程、持久訊息歷史；本地 preview 是使用者主動匯出，尚未遮罩，不作模型輸入直接外送。

完成紀錄：72 個測試通過；Ruff lint 通過；已實際執行 demo CLI，產生 3 則可用對話與來源檔。真實正文與伺服器暱稱驗收待提供請求者 ID／虛構對話所在頻道。
