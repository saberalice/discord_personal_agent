# 第一版功能規格

目前實作進度：工作票 06 已接入單批 Groq 摘要，待實機驗收。使用者確認本切片固定 gpt-oss-20b、可設定的 4,000 輸入／4,000 輸出 token、不硬限話題數；超量或錯誤明確失敗，不重試、不自動換模型。其餘第一版需求仍依切片逐步交付。

狀態：依截至 2026-09-11 的需求訪談整理；部分切片已實作。下列為已確認需求；未逐項詢問的工程預設集中於 [技術設計](design.md)，不冒充使用者已核准的數字。

技術方向已由使用者決定：第一版即採 LangChain，具體模組、套件及流程組合見技術設計；不是等未來再遷移的備選。

## 1. 問題與解法

使用者離開頻道一段時間後，可能累積 400～500 則對話。他需要快速知道什麼時候討論了什麼，再自行回到原文，不想從頭讀完。

第一版以 Discord Bot 讀取指定文字頻道的時間範圍，產生繁體中文討論時間線，回覆請求者的私訊。最初供 Owen 與朋友在測試伺服器使用，但從一開始支援多伺服器定位。公開 Bot API 未找到使用者已讀位置，因此產品稱為「時間範圍摘要」，不宣稱同步未讀；依據見 [平台研究](research/platform-constraints.md)。

## 2. 使用者故事

1. 作為請求者，我能貼上頻道連結，選擇最近幾小時，查詢不同伺服器的頻道。
2. 作為請求者，我能不填關注主題以了解全貌，也能填自然語言主題聚焦相關討論。
3. 作為請求者，我能在受理訊息看到固定的頻道與起訖時間，知道排隊不會改變查詢範圍。
4. 作為請求者，我能閱讀含時間定位與來源連結的摘要；需要時知道誰提出不同意見或承諾。
5. 作為請求者，我能直接讀卡片，長摘要則讀預覽並下載完整 TXT。
6. 作為請求者，我能取消排隊或處理中的任務，停止後續模型請求。
7. 作為未授權使用者，我能以共用免費額度開始使用，看到每日次數限制。
8. 作為個人模式使用者，我能透過外部官方頁面授權，使用自己的帳戶額度。
9. 作為使用者，我能用下拉選單切換模式與可選免費模型，並保留個人偏好。
10. 作為使用者，我能移除 Bot 保存的個人金鑰；失效或資料遺失時重新授權。
11. 作為頻道成員，我的內容只提供給原本有閱讀權限的請求者，並先經本機機密檢查。
12. 作為維護者，我能從本機設定調整時區、限制與遮罩規則，在 Linux 上管理單一實例。

## 3. 指令與操作

| 入口 | 行為 |
|---|---|
| `/help`、第一次使用 | 顯示用途、限制、共用／個人模式、外部授權說明 |
| `/summary channel:<連結> hours:<選填小時> limit:<選填則數> topic:<選填>` | 查單一文字頻道；連結定位伺服器與頻道，不需要額外 server 參數 |
| `/model` | 下拉選模式；個人模式另選核准免費模型；共用模式顯示預設模型 |
| `/settoken` | 提供官方授權外連與一次性授權碼提交介面；不要求把長效 Key 貼成訊息 |
| `/removetoken` | 移除本機個人金鑰及模型偏好，回到共用模式 |
| 受理訊息的取消按鈕 | 只允許任務本人操作，取消排隊或停止後續處理 |

使用者模式／模型選擇立即適用於下一個任務，不改變既有任務的憑證。共用模式不必刪除個人金鑰；個人金鑰失效或耗盡時停止，不自動消耗共用額度。

個人授權第一版支援 OpenRouter；共用模式可使用不同供應商，依免費條件與實際可完成的摘要量選型。個人金鑰代表使用個人帳戶額度，不保證增加免費額度或解鎖更高品質模型。

## 4. 訊息範圍

- `hours` 與 `limit` 皆選填；hours 為 1～24 小時，limit 為 1～500 則。
- 只填 hours：保留完整時段查詢，超過 500 則請使用者縮小範圍。
- 兩者皆不填：以收到指令的時間為截止，讀取最新最多 500 則，不限制起始時間。
- 只填 limit：讀取截止時間前最新最多 N 則；兩者皆填：讀取指定時段內最新最多 N 則（本次未明述組合採工程預設）。
- 回覆明示是完整時段查詢或最新最多 N 則，筆數模式不宣稱涵蓋整段歷史；所有模式皆不含截止時間。
- 截止時間固定為收到指令當下，受理時顯示；時區預設 `Asia/Taipei`，可設定。
- 單則文字不因產品字數門檻截斷；模型容量不足採分批，無法在限制內完整處理時明確失敗。
- 只處理指定文字頻道的文字，不展開討論串、不讀外部網頁、不分析附件內容。
- 圖片與附件使用通用佔位符，不推測內容；保留的網址仍須先檢查敏感資訊。
- 沒有訊息時直接告知；有訊息但找不到關注主題時，回覆範圍內未找到相關討論，不捏造。

模型輸入保留發言者與時間，跨日加日期標頭。例如：

```text
時區：Asia/Taipei（UTC+8）
日期：2026-09-10
小明 (15:03) : 週六副本幾點開始？
阿華 (15:05) : 我八點以後可以。
小明 (15:06) : [附件：圖片，未讀取內容]
```

名稱依伺服器暱稱、顯示名稱、使用者名稱取值；不同成員同名時加入單次任務內固定序號。姓名不一律匿名化，但名稱欄位同樣套用已設定的遮罩規則。

## 5. 回覆內容

- 依主題標示起訖時間，按開始時間排序；同主題隔很久續談可另列一段。
- 每段含原文定位，區分已確認事項與未定論；一般話題不逐一點名，提案、不同意見或承諾才列發言者。
- 繁體中文輸出，日期與時區清楚；回覆標示實際模型及額度來源。
- 正文不超過 3,500 字元用 Embed 顯示完整時間線；超過則前幾段預覽＋完整 UTF-8 TXT。
- 門檻可設定，最終格式仍受 Discord API 限制；預覽由既有摘要取得，不另呼叫 LLM。
- TXT 只含整理後的摘要與來源網址，不包含原始聊天紀錄。

## 6. 任務、額度與取消

| 設定 | 初始值 |
|---|---|
| 同時執行摘要任務 | 2 |
| 額外排隊任務 | 10 |
| 每人未完成任務 | 1（跨伺服器、跨模式） |
| 每人共用每日次數 | 3 |

參數、權限、遮罩檢查失敗不計每日次數；開始首次模型請求才計次，同任務分批／重試不重複計任務次數，但會消耗供應商額度。個人模式不受 Bot 共用每日次數限制，仍受並行、免費模型與供應商限制。

取消不保證供應商退回已送出請求的用量；取消成功後不再發新批次或啟動交付；若私訊已在傳送途中，結果可能已送達，需據實回報，不能保證撤回。重啟不恢復記憶體中的未完成任務；正常維護先停止新任務、等待執行中任務結束。

## 7. 機密、權限與保存

- 管理員明確知情的測試頻道才能使用；Bot 已加入目標伺服器，頻道在允許清單，請求者本人有檢視與閱讀歷史權限。
- 所有伺服器採用相同的模型／供應商允許政策與機密規則；各伺服器仍有各自的頻道 ID 清單。
- 本機先檢查整批來源，再外送。一般敏感欄位遮罩；命中禁止外送規則則整次停止，檢查失敗不送原文。
- 規則由 Owen 設定，一般使用者不能略過；不承諾偵測所有語境機密或繁中個資。
- 個人金鑰加密持久保存，加密主金鑰分開管理；不備份，遺失時重新授權。
- 模式與模型偏好可保存；聊天原文、摘要、原文對照只在任務記憶體中存在，完成／取消／失敗後清理。
- 日誌不含全文、金鑰、授權碼或完整偵測結果。Discord 本身仍保存回覆的私訊與附件。

## 8. 範圍外與驗證

第一版不含語音、自然語言自主呼叫工具、排程摘要、跨頻道整合、向量資料庫、摘要歷史查詢、付費模型或公開服務推廣。

第二階段需求為 Bot 直接加入語音頻道錄音，接 ASR／STT 逐字稿與可選摘要；先驗證語音接收、DAVE、錄音告知及主機能力，不以「可加入頻道」代表可錄音。

摘要品質由 Owen 在原型完成後人工驗證，再決定改進。權限隔離、憑證隔離、遮罩外送、固定時間範圍、取消與計次則以自動化行為測試驗證；詳見 [實作與驗證計畫](implementation.md)。


## 開發驗證介面：切片 B1

使用者已授權先完成訊息整理的小切片。提供本地預覽 CLI，套用既有選取與權限規則，分別輸出可閱讀對話及完整來源 JSON；不送出到第三方 LLM。依後續授權，現另提供下述暫時 Discord TXT 預覽。原始筆數先套用上限，再排除系統通知及無正文／附件項目，不補抓。使用目前可得暱稱，成員離開時回退全域名稱或 username。一般 Bot 對話可納入；附件只用通用佔位符，不解析嵌入／貼圖／投票的獨立欄位。

驗收：可檢查發言者、時間、順序、完整正文、附件佔位符與來源 ID；對權限拒絕、超量及 API 失敗明確停止。此開發匯出尚未遮罩，不代表完整產品允許繞過機密外送檢查。操作與驗收入口見 [對話預覽](conversation-preview.md)。

### 暫時 TXT 私訊交付

使用者已要求 `/summary` 將整理後對話以 TXT 私訊回傳給下指令者，接入 LLM 時移除。沿用權限與範圍規則，標示尚未遮罩／非摘要；無可用對話不產生空檔，附件在記憶體產生，超過應用層 8 MiB 時拒絕而不截斷。

切片 05 已將整批正文、暱稱及 topic 的本機 mask／block 套用到暫時 TXT 和本地預覽；先前的「尚未遮罩」是歷史階段狀態。自訂規則與已驗證範圍見 [機密規則指南](privacy-rules.md)。附件處理暫緩，LLM 及合併／重試／模型輸出檢查尚未實作。
